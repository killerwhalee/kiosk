## 1. 설치하기

### 필요한 것

| 무엇 | 역할 |
|---|---|
| **서버 컴퓨터** 1대 | 노트북, 데스크톱, 미니 PC 등. Windows·macOS·Linux 모두 됩니다. 행사 내내 켜 두어야 합니다. |
| **주문 입력 기기** 1대 이상 | 태블릿 권장(세로 화면). 휴대폰도 됩니다. |
| **주방 화면 기기** 주방마다 1대 | 태블릿이나 휴대폰. 알림음이 나야 하므로 스피커가 있어야 합니다. |
| **네트워크** | 모든 기기가 같은 와이파이에 연결되거나, [Tailscale](https://tailscale.com)로 연결되어 있어야 합니다. 인터넷 연결은 필요 없습니다. |

관리자 화면은 따로 기기가 없어도 됩니다. 서버 컴퓨터나 아무 기기에서 열면 됩니다.

### Node.js 설치

서버 컴퓨터에 [Node.js](https://nodejs.org) **18 이상**을 설치합니다. 홈페이지에서 LTS 버전을 받아 기본 설정으로 설치하면 됩니다.

설치가 되었는지 터미널(Windows는 명령 프롬프트나 PowerShell)에서 확인합니다.

```bash
node --version
```

`v18.0.0` 이상의 숫자가 나오면 됩니다.

### 프로그램 내려받기

둘 중 편한 방법을 고릅니다.

**Git을 쓰는 경우**

```bash
git clone https://github.com/killerwhalee/kiosk.git
cd kiosk
```

**Git을 쓰지 않는 경우**

1. GitHub 저장소 페이지에서 초록색 **Code** 버튼 → **Download ZIP**을 누릅니다.
2. 압축을 원하는 곳에 풉니다.
3. 터미널에서 압축을 푼 폴더로 이동합니다. (Windows에서는 폴더를 연 뒤 주소창에 `cmd`를 입력하고 Enter를 누르면 그 폴더에서 명령 프롬프트가 열립니다.)

`npm install`은 **하지 않아도 됩니다.** 실행에 필요한 외부 패키지가 없습니다.

## 2. 시작하기

프로그램 폴더에서 다음 명령을 실행합니다.

```bash
npm start
```

다음과 같이 출력되면 시작된 것입니다.

```
후원자 일일 찻집 주문 시스템이 시작되었습니다.
  이 컴퓨터에서: http://localhost:3000
  wlan0        http://192.168.0.12:3000

  주문 입력:   /order
  1번 주방   : /station/1
  2번 주방   : /station/2
  관리자:      /admin
  저장 파일:   /home/me/kiosk/data/state.json
```

- 첫 줄의 이름은 `config.json`의 `title`입니다.
- `http://192.168.0.12:3000`처럼 `localhost`가 아닌 주소가 **다른 기기에서 접속할 주소**입니다. 네트워크 연결이 여러 개면 주소도 여러 줄 나옵니다.
- 서버 컴퓨터에서 `http://localhost:3000`을 열어 시작 페이지가 보이는지 확인합니다.

### 종료와 재시작

- 종료: 터미널에서 `Ctrl + C`를 누릅니다.
- 재시작: 다시 `npm start`를 실행합니다. 들어와 있던 주문은 [저장 파일](#8-주문-데이터와-백업)에 남아 있으므로 그대로 이어집니다.
- **운영 중에는 터미널 창을 닫지 마세요.** 창을 닫으면 서버도 꺼집니다.
- 노트북이 절전 모드로 들어가면 서버가 멈춥니다. 전원을 연결하고 절전·화면 잠금 시간을 "안 함"으로 설정해 두세요.

### 처음 실행할 때 방화벽 경고가 뜨면

Windows나 macOS가 "node가 네트워크 연결을 받으려 합니다" 같은 창을 띄우면 **허용**을 누릅니다.
허용하지 않으면 서버 컴퓨터에서는 열리는데 다른 기기에서는 접속이 안 됩니다.

## 3. 태블릿 연결하기

### 같은 와이파이를 쓰는 경우 (가장 간단함)

1. 서버 컴퓨터와 모든 태블릿을 같은 와이파이에 연결합니다.
2. 태블릿 브라우저에서 서버 실행 시 출력된 주소를 엽니다. 예: `http://192.168.0.12:3000`
3. 시작 페이지에서 이 기기의 역할(주문 입력, 각 주방, 관리자)을 고릅니다.
4. 자주 쓰는 화면은 브라우저의 **홈 화면에 추가** 기능으로 바로가기를 만들어 두면 편합니다.

공유기를 껐다 켜면 서버 컴퓨터의 주소가 바뀔 수 있습니다. 서버를 다시 실행해서 출력되는 주소를 확인하세요.

> 학교·회사·카페의 공용 와이파이는 기기끼리 통신을 막아 두는 경우가 많습니다.
> 서버 컴퓨터에서는 열리는데 태블릿에서는 안 열린다면, 휴대용 공유기나 휴대폰 핫스팟을 쓰거나 아래의 Tailscale을 쓰세요.

### Tailscale을 쓰는 경우

[Tailscale](https://tailscale.com)은 서로 다른 네트워크에 있는 기기들을 하나의 사설망처럼 이어 줍니다. 공용 와이파이가 기기끼리 통신을 막거나, 휴대폰 데이터로 접속해야 할 때 씁니다.

1. 서버 컴퓨터와 모든 태블릿에 Tailscale을 설치하고 **같은 계정으로 로그인**합니다.
2. 서버 실행 시 출력되는 `tailscale0`(또는 `Tailscale`) 줄의 `100.x.y.z` 주소로 접속합니다.
3. MagicDNS를 켜 두었다면 `http://<서버 컴퓨터 이름>:3000`으로도 접속할 수 있습니다.

### (권장) HTTPS 주소 만들기

브라우저는 HTTPS 주소에서만 **화면 꺼짐 방지** 기능을 허용합니다. Tailscale을 쓰고 있다면 서버에서 아래 명령을 한 번 실행하면 HTTPS 주소가 만들어집니다.

```bash
tailscale serve --bg 3000
```

이후에는 `https://<서버 이름>.<tailnet 이름>.ts.net/station/1`처럼 접속합니다.

HTTPS를 쓰든 안 쓰든, 각 태블릿의 **화면 자동 꺼짐은 "안 함"으로 설정**해 두는 것을 권장합니다.

## 4. 설정 바꾸기

설정은 두 곳에서 바꿉니다.

- **`config.json`**: 가게 이름, 테이블 수, 주방 구성, 메뉴와 가격
- **환경 변수**: 포트, 관리자 PIN, 파일 위치

**어느 쪽이든 바꾼 뒤에는 서버를 다시 시작해야 반영됩니다.** (`Ctrl + C` → `npm start`)
서버를 재시작한 다음 태블릿 화면을 한 번 새로 고치면 확실합니다.

### config.json

프로그램 폴더의 `config.json`을 메모장 같은 텍스트 편집기로 엽니다. 저장소에 들어 있는 파일은 예시이므로 내용을 자유롭게 바꾸면 됩니다.

```json
{
  "title": "우리 동네 카페",
  "port": 3000,
  "tables": 8,
  "stations": [
    { "id": 1, "name": "음료" },
    { "id": 2, "name": "디저트" }
  ],
  "menus": [
    { "id": "americano", "name": "아메리카노", "price": 3000, "station": 1 },
    { "id": "latte", "name": "카페라테", "price": 3500, "station": 1 },
    { "id": "cake", "name": "치즈케이크", "price": 5000, "station": 2 }
  ]
}
```

#### `title`

모든 화면 맨 위와 브라우저 탭에 표시되는 이름입니다.

#### `port`

서버가 사용할 포트 번호입니다. 생략하면 `3000`입니다. 환경 변수 `PORT`가 있으면 그쪽이 우선합니다.
포트를 바꾸면 접속 주소의 `:3000` 부분도 바뀝니다.

#### `tables`

테이블 개수입니다. 주문 화면에 **1번부터 이 숫자까지** 테이블 버튼이 생기고, 그 범위를 벗어난 테이블 번호로는 주문할 수 없습니다.
테이블 없이 포장·대기번호로만 운영한다면 `1`로 두고 메모란을 활용하거나, 대기번호 개수만큼 지정해 테이블 번호를 대기번호처럼 써도 됩니다.

#### `stations` (주방)

음식이나 음료를 **준비하는 구역** 목록입니다. 주문이 들어오면 메뉴가 주방별로 나뉘어 각 주방 화면에 따로 뜹니다.

| 필드 | 설명 |
|---|---|
| `id` | 주방 번호. **1, 2, 3처럼 양의 정수**로 씁니다. 주방 화면 주소가 `/station/<id>`가 됩니다. |
| `name` | 화면에 표시되는 이름. 예: `"음료"`, `"1번 주방"`, `"그릴"` |

- 주방이 하나뿐이라면 하나만 적습니다. 모든 주문이 그 주방 화면 하나에 뜹니다.
- 주방이 셋 이상이어도 됩니다. 주방마다 기기를 한 대씩 두고 `/station/3`, `/station/4`…를 엽니다.
- 같은 주방 화면을 여러 기기에서 동시에 열어도 됩니다. 한쪽에서 처리하면 다른 쪽에도 바로 반영됩니다.

#### `menus` (메뉴)

| 필드 | 설명 |
|---|---|
| `id` | 메뉴를 구분하는 이름. **영문 소문자, 숫자, `-`, `_`만** 씁니다. 예: `americano`, `ice-tea` |
| `name` | 화면에 표시되는 메뉴 이름 |
| `price` | 가격(원). 숫자만 씁니다. `3,000`이나 `"3000원"`이 아니라 `3000` |
| `station` | 이 메뉴를 준비하는 주방의 `id` |

- 주문 화면에는 메뉴가 **적힌 순서대로** 나옵니다.
- `station`에는 반드시 `stations`에 있는 `id`를 적어야 합니다. 없는 주방 번호를 적으면 그 메뉴는 주문은 되지만 어느 주방 화면에도 뜨지 않습니다.
- 무료 메뉴는 `price`를 `0`으로 둡니다.

#### JSON 작성 시 주의할 점

`config.json`은 JSON 형식이라 작은 문법 오류에도 서버가 시작되지 않습니다. 서버가 오류를 내며 바로 꺼지면 다음을 확인하세요.

- 글자는 큰따옴표(`"`)로 감쌉니다. 작은따옴표(`'`)는 안 됩니다.
- 항목 사이에는 쉼표(`,`)를 넣고, **목록의 마지막 항목 뒤에는 쉼표를 넣지 않습니다.**
- 숫자(`price`, `tables`, `id`, `station`)는 따옴표 없이 씁니다. (메뉴 `id`는 글자이므로 따옴표를 씁니다.)
- 확인이 어렵다면 [JSONLint](https://jsonlint.com) 같은 사이트에 내용을 붙여 넣어 검사해 보세요.

#### 운영 중에 설정을 바꿀 때

주문이 이미 들어온 상태에서도 설정을 바꾸고 재시작할 수 있지만, 다음을 알아 두세요.

| 바꾸는 것 | 영향 |
|---|---|
| 메뉴 이름·가격 | 새 주문부터 적용됩니다. 이미 들어온 주문은 주문 당시의 이름·가격을 그대로 유지하므로 **총매출은 바뀌지 않습니다.** 다만 관리자 화면의 메뉴별 금액은 판매 수량 × 현재 가격으로 계산되므로, 행사 도중 가격을 바꾸면 메뉴별 금액의 합이 총매출과 달라질 수 있습니다. |
| 메뉴 추가 | 문제없습니다. |
| 메뉴 삭제 | 이미 들어온 해당 메뉴 주문은 남아 있지만, 관리자 화면의 메뉴별 판매 수량에서는 빠질 수 있습니다. 판매를 멈추려면 삭제 대신 관리자 화면의 **품절 처리**를 쓰세요. |
| 메뉴 `id` 변경 | 기존 주문과 연결이 끊깁니다. **운영 중에는 바꾸지 마세요.** |
| 메뉴의 `station` 변경 | 새 주문부터 적용됩니다. 이미 들어온 주문표는 원래 주방에 남습니다. |
| 주방 삭제·`id` 변경 | 그 주방에 걸려 있던 주문표가 화면에서 보이지 않게 됩니다. **운영 중에는 바꾸지 마세요.** |
| 테이블 수 | 새 주문부터 적용됩니다. |

품절 처리와 주문 취소는 설정 파일을 고칠 필요 없이 관리자 화면에서 운영 중에 바로 할 수 있습니다.

### 환경 변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | `config.json`의 `port`, 없으면 `3000` | 서버 포트 |
| `ADMIN_PIN` | 없음 | 설정하면 관리자 기능(품절·취소·초기화)에 PIN이 필요합니다 |
| `KIOSK_DATA` | `data/state.json` | 주문 저장 파일 위치 |
| `KIOSK_CONFIG` | `config.json` | 설정 파일 위치 |

환경 변수는 서버를 시작하는 명령 앞에 붙여서 지정합니다.

**macOS / Linux**

```bash
ADMIN_PIN=1234 npm start
ADMIN_PIN=1234 PORT=8080 npm start          # 여러 개 지정
```

**Windows (명령 프롬프트)**

```bat
set ADMIN_PIN=1234&& npm start
```

`1234`와 `&&` 사이에 공백을 넣지 마세요. 공백까지 PIN에 포함됩니다.

**Windows (PowerShell)**

```powershell
$env:ADMIN_PIN="1234"; npm start
```

#### `ADMIN_PIN` — 관리자 PIN

손님이나 다른 직원이 관리자 화면에서 주문을 취소하거나 초기화하지 못하게 하려면 설정하세요.
관리자 화면을 처음 열 때 PIN을 묻고, 같은 브라우저 탭에서는 다시 묻지 않습니다.
주문 입력과 주방 화면은 PIN 없이 쓸 수 있습니다.

#### `KIOSK_CONFIG`, `KIOSK_DATA` — 여러 행사용 설정 나눠 쓰기

행사마다 설정 파일과 저장 파일을 따로 두면, 같은 프로그램으로 여러 행사를 번갈아 운영할 수 있습니다.

```bash
KIOSK_CONFIG=configs/bazaar.json KIOSK_DATA=data/bazaar.json npm start
KIOSK_CONFIG=configs/festival.json KIOSK_DATA=data/festival.json npm start
```

포트를 다르게 주면 두 행사를 한 컴퓨터에서 동시에 돌릴 수도 있습니다.

```bash
KIOSK_CONFIG=configs/a.json KIOSK_DATA=data/a.json PORT=3000 npm start
KIOSK_CONFIG=configs/b.json KIOSK_DATA=data/b.json PORT=3001 npm start
```

## 5. 화면별 사용법

모든 화면 맨 위에는 서버 연결 상태(`연결됨 · 35ms`)가 표시되고, 왼쪽 위의 **처음 화면** 버튼을 누르면 시작 페이지로 돌아가 기기의 역할을 바꿀 수 있습니다.
주방 화면에서 나갈 때와 주문을 담는 중에 나갈 때는 한 번 더 확인합니다.

### 시작 페이지 (`/`)

이 기기에서 쓸 화면을 고릅니다. 주방 목록은 `config.json`의 `stations`에 따라 자동으로 만들어집니다.

### 주문 입력 (`/order`)

주문받는 직원이 씁니다. 세로로 세운 태블릿에 맞춰져 있습니다.

1. **테이블을 고릅니다.** 진행 중인 주문이 있는 테이블에는 건수가 표시됩니다. 테이블 버튼 아래에는 방금 들어온 주문 5건이 보입니다.
2. **메뉴 수량을 `+` / `−`로 정합니다.** 품절된 메뉴는 선택할 수 없습니다. 필요하면 요청사항(최대 100자)을 적습니다.
3. **주문 확인**을 눌러 내용과 합계 금액을 확인하고, **주문 전송**을 누릅니다.
4. 전송이 끝나면 몇 초 뒤 자동으로 첫 화면으로 돌아갑니다. **새 주문**을 눌러 바로 넘어갈 수도 있습니다.

전송 중에 연결이 끊겨 "전송 실패"가 나오면, 연결이 돌아온 뒤 **주문 전송**을 다시 누르면 됩니다. 같은 주문이 두 번 들어가지 않습니다.

### 주방 화면 (`/station/<번호>`)

각 주방의 서빙 담당이 씁니다. 그 주방이 만드는 메뉴만 보입니다.

1. 처음 열면 **시작하기**를 누릅니다. 브라우저 정책상 화면을 한 번 눌러야 알림음이 켜집니다.
2. 새 주문이 오면 **대기** 칸에 주문표가 생기고 화면 테두리가 깜빡입니다.
   대기 주문이 하나라도 남아 있으면 **주방에 요청할 때까지 3초마다 알림음이 계속 울립니다.**
3. 맨 위의 **"주방에 요청할 수량"**(예: `아메리카노 5개`)을 준비 담당에게 전한 뒤 **모두 주방에 요청**을 누릅니다.
   한 건씩 처리하려면 주문표마다 있는 **주방 요청** 버튼을 누릅니다.
4. 준비가 끝나면 테이블 번호를 보고 가져다준 다음 **서빙 완료**를 누릅니다.
5. 잘못 눌렀으면 되돌리기(↶) 버튼으로 이전 단계로 되돌립니다. 서빙 완료 목록은 접혀 있습니다.

- 주문 후 10분이 지나도 서빙되지 않은 주문은 경과 시간이 빨간색으로 표시됩니다.
- 화면 위의 종 모양 버튼으로 알림음을 켜고 끌 수 있습니다. 이 설정은 기기마다 따로 저장됩니다.

### 관리자 화면 (`/admin`)

운영 책임자가 씁니다. `ADMIN_PIN`을 설정했다면 처음 열 때 PIN을 입력합니다.

| 기능 | 설명 |
|---|---|
| **오늘 현황** | 총매출, 주문 수, 메뉴별 판매 수량·금액, 주방 주문표 진행 상태(대기 / 주방 요청 / 서빙 완료). 취소된 주문은 빠집니다. |
| **메뉴 품절 관리** | 재료가 떨어진 메뉴를 품절로 표시합니다. 주문 화면에서 바로 선택할 수 없게 됩니다. 다시 누르면 판매 재개. |
| **화면 바로가기** | 주문 입력·주방 화면으로 이동 |
| **주문 목록** | 진행 중 / 전체 / 취소됨으로 걸러 봅니다. 잘못 들어간 주문은 **주문 취소**(주방 화면에서도 바로 사라짐), 실수로 취소했으면 **취소 철회**. |
| **전체 초기화** | 모든 주문과 품절 표시를 지웁니다. 리허설 주문을 지울 때나 다음 날 새로 시작할 때 씁니다. 지우기 전 자동으로 백업 파일을 만듭니다. |

## 6. 당일 운영 체크리스트

**행사 전**

- [ ] `config.json`에 가게 이름, 테이블 수, 주방, 메뉴·가격 입력
- [ ] 필요하면 `ADMIN_PIN` 정하기
- [ ] 서버 컴퓨터 전원 연결, 절전 모드·화면 잠금 끄기

**행사 당일 시작 전**

- [ ] 서버 컴퓨터에서 `npm start` 실행 (터미널 창은 닫지 않기)
- [ ] 주문 기기에서 `/order`, 각 주방 기기에서 `/station/<번호>` 열기
- [ ] 주방 화면에서 **시작하기**를 누르고 알림음 소리 확인 (미디어 음량 최대, 무음 모드 해제)
- [ ] 리허설 주문을 넣어 각 주방 화면에 제대로 뜨는지 확인
- [ ] 관리자 화면에서 **전체 주문 초기화**로 리허설 주문 지우기
- [ ] 모든 태블릿의 화면 자동 꺼짐 끄기, 충전기 연결

**행사 후**

- [ ] 관리자 화면에서 최종 매출과 메뉴별 판매 수량 확인 (화면을 캡처해 두면 편합니다)
- [ ] 필요하면 `data/state.json` 파일을 다른 곳에 복사해 보관
- [ ] 서버 종료 (`Ctrl + C`)

## 7. 문제가 생기면

| 증상 | 대처 |
|---|---|
| `npm start` 하자마자 오류가 나며 꺼짐 | 대부분 `config.json` 문법 오류입니다. [JSON 작성 시 주의할 점](#json-작성-시-주의할-점)을 확인하세요. `EADDRINUSE`가 보이면 그 포트를 다른 프로그램(또는 이미 켜 둔 서버)이 쓰고 있는 것이므로, 그 프로그램을 끄거나 `PORT`를 바꿉니다. |
| `node` / `npm` 명령을 찾을 수 없음 | Node.js가 설치되지 않았거나, 설치 후 터미널을 다시 열지 않은 경우입니다. 터미널을 닫았다가 다시 엽니다. |
| 서버 컴퓨터에서는 열리는데 태블릿에서 안 열림 | 같은 와이파이인지, 방화벽에서 node를 허용했는지 확인합니다. 공용 와이파이라면 기기 간 통신이 막혀 있을 수 있으니 핫스팟이나 Tailscale을 씁니다. |
| 연결 표시 옆 숫자(예: `연결됨 · 35ms`) | 서버까지 왕복 지연 시간입니다. 5초마다 갱신되며 300ms 이상이면 점이 노란색으로 바뀝니다. 계속 노랗다면 와이파이 신호를 확인하세요. |
| 화면 위에 **"연결 끊김"**이 빨갛게 표시됨 | 와이파이·Tailscale 연결과 서버가 켜져 있는지 확인합니다. 연결이 돌아오면 자동으로 다시 연결되고, 최신 주문을 전부 다시 받아옵니다. |
| 주문 전송 중 "전송 실패" | 연결이 돌아온 뒤 **주문 전송**을 다시 누릅니다. 같은 주문이 두 번 들어가지 않습니다. |
| 알림음이 안 울림 / 작음 | 기기 미디어 음량을 최대로 올리고, 무음 모드(아이폰·아이패드는 옆면 무음 스위치)를 끕니다. 화면 위의 종 모양 버튼이 켜져 있는지 확인하고, 페이지를 새로 고쳤다면 **시작하기**를 다시 누릅니다. 주방이 시끄럽다면 블루투스 스피커를 연결하는 것도 방법입니다. |
| 메뉴가 주방 화면에 안 뜸 | `config.json`에서 그 메뉴의 `station`이 실제 주방 `id`와 같은지 확인합니다. |
| 설정을 바꿨는데 화면이 그대로 | 서버를 재시작했는지 확인하고, 태블릿 화면을 새로 고칩니다. |
| 잘못 들어간 주문 | 관리자 화면 → 주문 목록 → **주문 취소**. 주방 화면에서도 바로 사라집니다. |
| 메뉴 재료 소진 | 관리자 화면 → **품절 처리**. 주문 화면에서 해당 메뉴를 선택할 수 없게 됩니다. |
| 관리자 PIN을 잊어버림 | 서버를 종료하고 새 `ADMIN_PIN`으로 다시 시작합니다. 주문은 그대로 남아 있습니다. |
| 서버가 꺼졌다 켜짐 | 주문은 저장 파일에 남아 있으므로 `npm start`로 다시 켜면 그대로 이어집니다. |

## 8. 주문 데이터와 백업

- 모든 주문과 품절 표시는 변경될 때마다 **`data/state.json`** 파일에 바로 저장됩니다. (`KIOSK_DATA`로 위치를 바꿀 수 있습니다.)
- 서버가 갑자기 꺼져도 이 파일이 남아 있으므로 다시 켜면 이어서 운영할 수 있습니다.
- 관리자 화면에서 **전체 초기화**를 하면, 지우기 전 내용을 `state.json.backup-<시각>` 파일로 자동 보관합니다. 실수로 초기화했다면 서버를 끄고 이 백업 파일의 이름을 `state.json`으로 바꾼 뒤 다시 켜면 됩니다.
- 저장 파일이 손상되어 읽을 수 없으면, 서버는 그 파일을 `state.json.broken-<시각>`으로 옮겨 두고 빈 상태로 시작합니다.
- 완전히 새로 시작하고 싶다면 서버를 끈 상태에서 `data` 폴더를 지우면 됩니다.
- `data` 폴더는 Git에 올라가지 않도록 설정되어 있습니다.
